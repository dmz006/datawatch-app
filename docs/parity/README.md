# Cross-client parity matrix — PWA ↔ Android ↔ iOS

**Rule 1 — PWA drives design.** The live PWA (`dmz006/datawatch` → `internal/server/web/app.js`,
`style.css`, `index.html`) is the reference for layout, copy, colors, menus, animations and
behaviour. The May spec (`docs/plans/2026-05-12-pwa-full-spec.md`) is a map, not the authority —
the live code wins where they differ.

**Rule 2 — the user makes every judgment call.** Rows where a client deliberately differs, where a
mobile app may have the *better* idea, or where "n/a on this platform" is arguable are flagged
`needs-decision` and listed under *Decisions needed*. Nobody resolves them in the matrix.

**Rule 3 — capture all drift**, not just iOS gaps: Android↔PWA differences are rows too.

## Row schema (every section uses exactly this table)

```
| Cat | Feature | PWA | Android | iOS | Status | Decision | Notes |
```

- **Cat**: `data` (endpoint / WS frame), `element` (card, field, pill, badge), `interaction`
  (tap, long-press, menu, sheet, dialog, swipe, drag, FAB), `motion` (animation, transition,
  splash, loading state — give duration/easing when known), `token` (color, type, spacing,
  icon), `string` (copy / i18n), `nav` (routing, back behaviour, deep link).
- **PWA / Android / iOS**: `✓ ref` when present (ref = `file:line` or function/composable/view
  name), `✗` when absent, `~ ref` when present but different. Be terse; refs matter more than prose.
- **Status**: `aligned` · `ios-missing` · `android-missing` · `pwa-missing` (an app has it, PWA
  doesn't — candidate "app had a better idea") · `misaligned` (all have it, differently) · `n/a`
  (platform-inappropriate, e.g. hover, drag-reorder on watch).
- **Decision**: blank, or `needs-decision` — then add a numbered entry under *Decisions needed*
  stating the options neutrally. Mechanical `ios-missing` rows need no decision.
- **Notes**: one line max.

Each section file ends with:

```
## Coverage
rows: N · aligned: a · ios-missing: b · android-missing: c · pwa-missing: d · misaligned: e · n/a: f

## Decisions needed
1. <question> — options: (a) … (b) … — refs
```
