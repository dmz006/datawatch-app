## Decisions needed
1. **Splash gating** — options: (a) PWA rule on both apps: show on first launch, after an app/daemon version change, or >24 h since last, else skip; (b) Android's every-cold-launch 3.2 s brand moment becomes the rule (PWA adopts); (c) each keeps its own — app.js:309-343, AppRoot.kt:174-210.
2. **Android splash extras** (status line "unlocking vault… → ready", Settings → About "Replay splash") — options: (a) adopt in PWA + iOS as the brand standard; (b) keep Android-only; (c) drop from Android — AppRoot.kt:175-198, `Destinations.SplashReplay`.
3. **Sessions header title** — options: (a) PWA "Datawatch" everywhere; (b) Android's server-name picker title (multi-server is an app capability); (c) iOS "Sessions" + server chip — app.js:1853, SessionsScreen.kt:191, SessionsView.swift:48.
4. **Server-picker placement on iOS** — options: (a) match Android: dropdown in header title with edit/add; (b) keep iOS in-content segmented control; (c) both — HeaderComponents.kt `SingleServerPickerTitle`, ObserverView.swift `profilePicker`.
5. **Alert pill colours** — the PWA mixes a blue tint bg rgba(96,165,250,.18) with a purple `--accent2` border; Android uses blue/blue (#60A5FA); iOS has a bell + red badge, no pill. Options: (a) fix PWA to blue border and apps copy the pill; (b) PWA as-is (blue bg / purple border) copied exactly; (c) iOS keeps native bell — app.js:929-940, HeaderComponents.kt `AlertsBellAction`, AlertsBellButton.swift.
6. **Status-dot gestures** — PWA: triple-click → debug panel, long-press → reconnect + update check; apps: tap → sheet (status, last probe, Retry). Options: (a) apps add long-press reconnect + hidden debug entry; (b) PWA adopts the tap-sheet; (c) leave — app.js:15320-15333, 15372.
7. **Chrome metrics** — how far should mobile mimic PWA chrome (56/60px bars with 1px borders, circular accent2 FAB, 2px active-tab top border) versus platform-native M3 / UIKit chrome? Options: (a) native chrome, PWA colours only (current); (b) custom bars reproducing PWA metrics on both apps.
8. **Nav icons on iOS** — options: (a) emoji glyphs like PWA/Android (🖥 🤖 ⚠ 📡 ☷ ⚙); (b) keep SF Symbols; (c) SF Symbols everywhere incl. Android — index.html:104-150, BottomNavBar.kt `NavGlyph`, RootView.swift `iconName`.
9. **Alerts tab badge at zero** — Android shows an always-on dimmed badge and 🔕 when muted (Sprint 22 #115); PWA hides it at 0 and has no muted state on the tab. Options: (a) PWA rule (hide at 0) on both apps; (b) Android's always-on + muted becomes the rule — BottomNavBar.kt:97-120, app.js:16304-16312.
10. **Wide-screen model** — PWA 480px card + expand toggle; Android two-pane ≥600dp; iOS `NavigationSplitView` sidebar. Options: (a) accept per-platform; (b) define one tablet layout (list + detail two-pane) for both apps and the expanded PWA.
11. **Restore last view/session on cold start** — PWA does (`cs_active_view`/`cs_active_session`); apps start on Sessions. Options: (a) apps restore last tab (+ open session); (b) tab only; (c) leave — app.js:1727-1729.
12. **Deep-link scheme** — Android registers `dwclient://session/<id>`; iOS code expects `datawatch://` plus `https://datawatch.app/...` universal links but registers no scheme (dead). Options: (a) `dwclient://` on both; (b) `datawatch://` on both (Android manifest change); and whether to pursue universal links (needs an owned domain + AASA file) — AndroidManifest.xml:51-54, AppRouter.swift, Info.plist.
13. **Android platform integrations in iOS scope** — assist/voice intents, widgets, Quick Settings tile. Options: (a) iOS equivalents (Siri Shortcuts / App Intents, WidgetKit) are parity items; (b) out of scope for 1:1.
14. **iOS first run** — options: (a) adopt Android's Splash → Onboarding → Add Server flow; (b) keep per-tab empty states; (c) PWA-style minimal (no onboarding) on both apps — OnboardingScreen.kt, AutomataView.swift `noProfilesView`.
15. **`--accent`** — PWA/iOS #7C3AED vs Android #8B5CF6 (BL28 WCAG AA on dark). Options: (a) PWA + iOS adopt #8B5CF6 (app had the better idea); (b) Android reverts to #7C3AED — Theme.kt:33, style.css:28, DatawatchColors.swift.
16. **UI typeface** — PWA renders all UI in JetBrains Mono 14px; both apps use the platform sans (Roboto / SF Pro) with mono only for terminals. Options: (a) mono UI on mobile for 1:1; (b) sans stays on mobile (platform convention) and this is an accepted difference; also whether iOS Dynamic Type scaling is desired — style.css:69, Theme.kt, DatawatchFonts.swift.
17. **Brand casing** — "Datawatch" (PWA manifest + header) vs "datawatch" (PWA splash, both apps, ASC). Options: (a) lowercase everywhere incl. PWA header/manifest; (b) capitalised everywhere.
18. **Android toasts** — PWA retired toasts (alpha.29 #271, everything routes to the alert dock); Android still has `DatawatchToast.kt`. Options: (a) retire on Android, dock only; (b) keep — app.js:14988-15000.
19. **Loading indicator standard** — Android's animated eye + pulsing label vs PWA CSS spinner vs iOS system spinner. Options: (a) Android eye becomes the standard (PWA + iOS adopt — iOS currently uses an SF-symbol eye); (b) plain spinners everywhere — DatawatchLoadingContent.kt, SessionLoadingOverlay.swift.
